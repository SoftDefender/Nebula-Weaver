# 技术债、风险与优化策略

## A. 技术债总览
1. 架构风险
- [事实] 多工具共享单一前端包体，缺少按工具拆分与懒加载。
2. 模块耦合问题
- [事实] 每个工具内部高度自洽，但跨工具复用层薄（任务编排/错误处理重复）。
3. 状态管理问题
- [事实] 全局无统一状态容器；长流程状态分散在组件内部。
4. 数据一致性问题
- [事实] Nebula 导出扩展名和实际编码容器可能不一致。
5. 可测试性问题
- [事实] 无测试脚本、无测试文件、无 CI。
6. 可部署性问题
- [事实] 仓库未体现部署流水线和环境门禁。
7. 可观测性问题
- [事实] 无统一日志/埋点/错误上报。
8. 性能风险
- [事实] 构建单 chunk 1.4MB；图形和批处理大多在主线程执行。
9. 安全或配置风险
- [事实] API key 注入前端构建变量，存在暴露面。
10. 新人接手成本来源
- [事实] README 范围过窄、无系统级交接文档（本次已补齐）。

## C. 低风险优化建议（立即可做）
### L1 修复 Nebula 导出扩展名一致性
- 问题描述：下载文件名固定 `.mp4`，可能与实际编码不一致。
- 证据：`App.tsx:261`; `NebulaCanvas.tsx:526-533`。
- 影响范围：Nebula 导出用户。
- 风险等级：中。
- 优化方案：按 `MediaRecorder.mimeType` 或用户选择映射扩展名。
- 预期收益：减少播放器兼容问题与用户困惑。
- 实施前提：导出回调返回 MIME 或 format 信息。
- 可能副作用：历史脚本依赖固定命名时需同步。
- 是否建议现在做：是。

### L2 清理未接通状态与配置
- 问题描述：`previewTrigger/onImageReady/environment/preserveMetadata/maintainAspectRatio` 等存在“声明未生效”。
- 证据：对应文件行号已在模块文档列明。
- 影响范围：多模块可维护性。
- 风险等级：中。
- 优化方案：删除死代码或补齐最小可用实现并加注释。
- 预期收益：降低认知噪音、减少误判。
- 实施前提：确认是否为近期 roadmap。
- 可能副作用：若后续计划使用需重新接线。
- 是否建议现在做：是（先标注后删除）。

### L3 增加最小质量门禁脚本
- 问题描述：当前无 lint/test 命令。
- 证据：`package.json`。
- 影响范围：全仓库回归质量。
- 风险等级：高（现状风险高，改动风险低）。
- 优化方案：新增 `lint`、基础 `typecheck`、最少 smoke 测试脚本。
- 预期收益：降低回归概率。
- 实施前提：确定 lint 规则基线。
- 可能副作用：首次接入会暴露大量历史告警。
- 是否建议现在做：是。

## D. 中期优化建议（局部改动成本）
### M1 前端分包与延迟加载
- 问题描述：单大包导致冷启动压力。
- 证据：构建输出警告。
- 影响范围：首页进入与首次切换工具。
- 风险等级：中。
- 优化方案：按工具 `React.lazy` + 动态 import；three 与 heavy service 独立 chunk。
- 预期收益：降低首屏体积与内存峰值。
- 实施前提：补充路由级 loading/error fallback。
- 可能副作用：首次进入某工具会出现延迟加载。
- 是否建议现在做：是。

### M2 统一批处理任务引擎
- 问题描述：Framer/Shrink/Nebula 各自实现进度与取消，重复高。
- 证据：三个工具各自维护 `isProcessing/isExporting` 与循环。
- 影响范围：多工具维护成本。
- 风险等级：中。
- 优化方案：抽取 `useBatchTaskRunner`（进度、取消、错误聚合、重试）。
- 预期收益：减少重复代码，统一用户体验。
- 实施前提：先定义通用任务接口。
- 可能副作用：短期重构引入回归风险。
- 是否建议现在做：建议在一个迭代内实施。

### M3 资源释放一致化
- 问题描述：URL/canvas/three 对象清理路径不统一。
- 证据：模块中存在分散 revoke/dispose。
- 影响范围：长会话稳定性。
- 风险等级：中。
- 优化方案：封装 `resourceRegistry`，在删除/卸载/异常路径统一释放。
- 预期收益：降低内存泄漏风险。
- 实施前提：梳理各工具生命周期钩子。
- 可能副作用：误释放导致对象失效。
- 是否建议现在做：是（中期）。

## E. 长期演进建议（架构级调整）
### H1 AI 调用安全收敛
- 问题描述：API key 直入前端，不适合长期生产。
- 证据：`vite.config.ts` 注入。
- 影响范围：Nebula AI 能力与安全合规。
- 风险等级：高。
- 优化方案：引入轻量后端代理签名/限流层，前端不持久暴露主密钥。
- 预期收益：安全性提升，便于配额治理。
- 实施前提：有可部署后端通道。
- 可能副作用：架构复杂度上升。
- 是否建议现在做：视产品上线计划决定，若公网开放则应尽快。

### H2 观测性平台化
- 问题描述：无统一错误与性能追踪。
- 证据：仅 console 日志。
- 影响范围：全站运维与缺陷定位。
- 风险等级：高。
- 优化方案：接入前端错误上报 + 性能指标 + 关键行为埋点。
- 预期收益：问题可追踪、可量化。
- 实施前提：确定监控平台与数据合规策略。
- 可能副作用：埋点成本和隐私合规管理负担。
- 是否建议现在做：建议分阶段接入。

### H3 模块平台化与插件化边界
- 问题描述：多工具共壳但共享协议薄弱，扩展新工具成本会增加。
- 证据：工具间缺通用任务/配置/日志协议。
- 影响范围：中长期迭代效率。
- 风险等级：中。
- 优化方案：定义工具插件接口（生命周期、任务、导出、观测 hooks）。
- 预期收益：新功能可插拔，降低耦合。
- 实施前提：先稳定现有四工具行为模型。
- 可能副作用：短期重构工作量较大。
- 是否建议现在做：暂不立即做，先完成中期基础治理。
