# 21 - Nebula-Weaver 缺陷修复工作流（4173 本地问题专项）

## 目标
面向已上线本地版本（4173）的真实故障，建立可复用、可递归、可交付的修复闭环。

## 工作流总览
1. 问题现象分析（递归到根因）
2. 根因修复方案制定（细化到步骤）
3. 方案评估与迭代（组件/风险/可优化项）
4. 执行代码修复
5. 本地编译部署与修复验证

---

## 阶段1：问题现象分析（递归到根因）
### 1.1 输入材料
- 现象描述（用户可复现步骤）
- 设计材料/需求说明（若有）
- 当前实现代码
- 运行日志与控制台异常

### 1.2 递归分析模板
对每个问题使用以下结构，至少递归 2 层：
- 现象：发生了什么
- 直接原因：为什么会出现该现象
- 深层原因：为什么代码会这样实现/漏掉该逻辑
- 根因结论：可修复的最小根因点（1~N）

### 1.3 输出要求
- 以 `[事实]/[推断]/[待验证]` 标注结论
- 每个根因关联到具体文件与函数

---

## 阶段2：根因修复方案制定
### 2.1 方案拆分
按根因分为可执行小项（每项必须可独立回归）：
- 改哪些组件/服务
- 变更点是什么
- 预期行为如何变化
- 如何验证

### 2.2 细化标准
每项必须包含：
- 代码修改点（文件、函数、状态）
- 边界处理（异常/兼容/回退）
- 验证用例（正向+逆向）

---

## 阶段3：方案评估与迭代
### 3.1 评估维度
- 涉及组件与调用链
- 改动面风险
- 向后兼容性
- 可观测性（日志/状态可见）
- 可测试性

### 3.2 迭代规则
若任一项不满足“低歧义、可回归、风险可控”，返回阶段2重写。

---

## 阶段4：执行代码修复
### 4.1 执行要求
- 按小项顺序提交修改
- 每修复一个问题立即执行该问题的缺陷回归
- 不跨问题混改未验证逻辑

### 4.2 回归分类
- 问题级回归：只验证该问题对应链路
- 阶段冒烟：验证核心主路径不回归

---

## 阶段5：本地编译部署与修复验证
### 5.1 必跑项
- `npm run build`
- `npm test`
- 集成/端到端回归（`audit:phase4`、`audit:phase5`、`audit:full`）

### 5.2 验收门禁
全部满足才可判定阶段完成：
- 问题级回归全部通过
- 阶段冒烟通过
- 全量单测通过
- 全量集成回归通过
- 产物文档更新

---

## 本轮执行记录（2026-03-30）

### P1 图片拖拽导入失败
- [事实] 仅存在 `#neb-upload` 文件选择输入，未实现画布区域 `dragenter/dragover/drop` 处理。
- [修复] 在 Nebula 中央画布容器新增拖拽事件处理与可视化拖拽提示层，并复用统一文件导入链路（过滤非图片）。
- [回归] 拖拽图片至画布可直接入队；普通上传入口仍可用。

### P2 外开组件缺失（FPS、十字星芒、图层隐显/删除）
- [事实] 状态层已有 `videoConfig.fps`、`particleConfig.spikeGain/spikeThreshold/spikeAngle`，但右侧无对应 UI。
- [事实] 左侧队列项无单层隐显/删除按钮。
- [修复]
  - 新增 `Frame Rate` / `Bitrate` / `Container` 导出控制组件；
  - 新增 `Star Spikes` 参数组件（Gain/Threshold/Angle）；
  - 左侧队列新增单项显隐与删除操作，并加入状态联动（当前活动项删除时索引自动回退）。
- [回归] 参数可调且生效，图层显隐/删除操作可用，导出按钮对隐藏图层自动禁用。

### P3 导出视频异常（2s/黑屏/不可播放/不可识别）
- [事实] 导出默认参数为 `mp4 + 40Mbps + 60fps`，在浏览器 MediaRecorder 兼容性下易产生不稳定文件。
- [事实] 录制时画布尺寸会做偶数对齐；1x1 图被对齐为 0x0，导致录制失败或空结果。
- [修复]
  - 默认导出改为 `webm + 12Mbps + 30fps`；
  - 增加录制配置收敛（移动端/桌面端 FPS 与码率限幅）；
  - 增加 MIME 自动探测与回退策略（优先请求格式，失败回退 webm）；
  - 录制结束增加空输出防护；
  - 画布尺寸对齐增加最小值保护（最小 2x2，避免 0x0）。
- [回归]
  - `audit:phase5` 通过（含默认导出与“禁用 mp4 支持”场景）；
  - 导出文件可被脚本捕获，扩展名与 MIME 匹配。
